# EcoCapture-Web 0.2.0 / EcoLogger V2

UNO Q上で動く実測ロガーです。IMU、GNSS、CANの値をSTM32が取得し、SDへ独立記録します。Linux側はWeb画面と内蔵eMMCのCSV記録を担当します。PCやブラウザで測定値を生成しません。

## 開く・記録する

USB接続後、`Open-EcoCapture-Web.ps1` を実行し、http://127.0.0.1:8080/ を開きます。既に転送設定がある場合はURLを開くだけです。

- 電源投入でSTM32のSD記録が始まります。Web側も初期設定ではCSVを自動記録します。
- Dashboardの「記録停止」で両方を停止し、Loggingの一覧から保存済みファイルをダウンロードします。
- eMMCのCSV、CANの生フレーム、メタデータを個別に取得できます。
- SDの `EL000001.BIN` などは元のIMU/GNSS/CANデータを含みます。SD一覧のダウンロードは記録停止後に行います。Web経由のSD転送には時間がかかります。
- `python sd_decode.py EL000001.BIN` でCSVとCAN JSONLへ変換できます。全ブロックのCRCと連番を確認し、破損はエラーにします。WindowsでもPython標準ライブラリだけで動きます。
- 保存済みCSVの「SDへコピー」はFAT32へコピーし、書き込んだセクタを読み戻して照合します。記録停止中だけ使用できます。SDの既存ファイルを自動で削除・フォーマットしません。

ブラウザを閉じても記録は続きます。LinuxのWebアプリを止めてもSTM32のSD記録は続きます。USBが唯一の給電元なので、ケーブルを抜くと電源も失われます。

## 測定・表示

IMUはBNO055、NDOF・100Hz。加速度、角速度、姿勢、四元数、校正状態と元レジスタを保存します。割り込みは高加速度イベントです。この個体のFW03.11にはデータ準備完了割り込みがないため、サンプル取得には100Hzタイマーを使います。車体軸への変換と取付後の校正は実車で確認してください。

GNSSはMAX-M10Mの4衛星系統・10Hz。192MHz用の永久設定はこの個体で適用済みで、通常起動や更新ではOTPへ書き込みません。アンテナなし・測位なしの場合、位置と速度は空欄にします。GNSSのiTOWとUTCを元データに残します。PPSの割り込みはIMUと同じEXTI1を使うため有効にしていません。

CAN1/2ともClassic CAN・受信専用です。125/250/500/1000kbpsを選択できます。通常動作で送信しません。Settingsの信号定義でID、標準/拡張、符号、バイト順、スケール等を指定できます。1秒以上届かない値は空欄になります。初期値は500kbps。2026-10-03に両端120ΩのCAN1/CAN2外部折返しを各速度で検証し、標準/拡張ID、DLC 0〜8、合計14,400フレームが一致しました。SD切替を含む約100フレーム/秒の試験です。CAN FD、高負荷の実車通信は未検証です。

LTE送信は初期状態OFFです。SIM7070の内蔵TCPを使うPodiumクライアントと設定画面を追加しました。SIM・LTEアンテナ・APN・Podium送信キーを揃えてから、Settings → UNO Q → LTE / Podiumで送信を開始します。2026-10-03にSORACOM planX3 X3-5MBでドコモLTE-M Band 19への登録、DNS、TCP、短いHTTP応答を確認しました。起動直後のSIM準備待ちを修正し、最終5回の電源再投入接続が成功。Podiumは送信キー未設定のため未検証です。5MB枠を考慮し、LTEはOFFのまま、検証通信を短いヘッダーのみに限定します。PPPは不要な構成で、Linux全体をLTEでオンラインにする機能はありません。TVSを外して復旧した状態なので、保護部品の交換は別途必要です。カメラは未接続です。

## ラップ計測

Settings → 基本設定 / CAN の「ラップ計測」で、コントロールライン上（測位中）で「ここをラインにする」を押します。止まったまま登録した場合は、最初に通過したときの進行方向を覚え、以後はその向きの通過だけを数えます。ライン幅（初期30 m）と最短ラップ（初期60秒）を変えられます。記録中でも変更できます。

時刻はGNSSのUTCで、Linuxの時計は使いません。連続する3D測位（間隔1秒以内・水平精度25 m以内）の間でラインを横切ったときだけ数えます。周回数・ラップは `lap.json` に保存し、再起動後も続きから数えます。レース開始前に「周回数をリセット」を押します。最大ラップ（初期3600秒）より長い間隔の通過は数えずに、そこから新しいラップを始めます。

Dashboardに周回・現在ラップ・前回・ベストを表示し、eMMCのCSVに `LapCount`・`CurrentLap`・`LapTime`・`BestLap`・`ElapsedTime`（RaceCapture準拠、時間は分単位）を追加しました。Podiumにも常に送ります（ライン未設定の間は空欄）。STM32のSD記録にはラップは入りません（GNSSから後で再計算できます）。

Podium送信は Settings → UNO Q で **自動／LTEだけ／Wi-Fiだけ（試験）** を選べます。**本番は「自動」**：UNO QのWi-Fiがつながっていれば Wi-Fi で送り、つながっていなければ LTE で送ります。Wi-Fiで送信中に Wi-Fi が切れたら（コースに出たら）2秒以内に気づき、待たずに LTE へ移ります（切れてから30秒は Wi-Fi を試しません）。LTEで送れている間は Wi-Fi に戻りません。Wi-Fiの通信には「送ったデータに5秒返事が無ければ切断」（`TCP_USER_TIMEOUT`）を付け、電波が弱くつながったまま通らない状態でも抜けます。切替の記録は `GET /api/podium/events`。**本番で「自動」を使うのは `podium_auto_link_test_plan.md` の実機試験を全部通してから**。Wi-FiはUNO Q自身のネット接続を使い、APN・SIMの確認は不要です。

## 保存先・障害時

Linux: `/home/arduino/ecocapture-v2-data/logs` にCSV、CAN JSONL、メタデータ。1秒ごとにflush/fsyncします。**eMMCの記録はSDとは独立**で、SDが未認識・異常・開始失敗でも記録を始め、画面に「● REC（本体のみ）」と警告を出します。容量は**ドラレコ方式**で、空きが1GiB（環境変数 `ECOCAPTURE_KEEP_FREE_BYTES`）を切ると記録が終わったログを古い順に消します（記録中のファイルは消さない）。消せるものが無く空き256MiBを下回った場合だけeMMC記録を停止します。再起動で中断されたCSVはメタデータを `interrupted` にします。設定は同データディレクトリの `config.json` です。

SD: 512バイトセクタのFAT32プライマリパーティションに対応します。1MiB単位で空き領域を予約し、`ELxxxxxx.BIN` を作成します。実測データは65,536バイトの待ち行列を通して専用スレッドが保存し、満杯で次ファイルへ切り替えます。既存ログを上書きする循環記録は行いません。カード満杯、連続した1MiBの空き不足ではSD記録エラーを表示し、eMMCの記録は継続します。ファイルサイズは1秒ごとに更新するため、突然の電源断では末尾約1秒がファイルに現れない可能性があります。

現在の怪しい16GBカードは既存の256MiB FAT32パーティションを使っています。全容量を使うには、必要なデータを退避して別途パーティションを準備してください。

ログの `host_utc` はLinux受信時刻、`mcu_ms` はMCU起動からの経過時間です。GNSS UTCは測位系の時刻情報で別項目です。欠落数はBridge用待ち行列とSD用待ち行列を区別して確認します。

## 更新・起動

WindowsからWebとMCUを両方更新:

```powershell
powershell -ExecutionPolicy Bypass -File .\EcoCapture-Web\Update-UNOQ.ps1 -Firmware
```

事前に記録を停止します。このインストール済みUNO QのArduino core、ライブラリ、Dockerベースイメージを使います。別の未セットアップ基板用のワンクリック環境構築ではありません。

UNO Q内での更新は `deploy.sh` と `build-mcu.sh`。ソースは `firmware/ecologger_v2`。MCUの実際の書き込み領域は64KiBなので、ビルドで不要シンボルを整理してサイズを検査します。Arduino RouterBridgeの更新スレッドのスタックを8192バイトへ修正し、RPC受信バッファを1024バイトへ拡張し、MCUとLinuxルーターを921600bpsへ揃えます。

`ecocapture-mcu-start.service` が起動時にMCUを開始し、`ecocapture-web-start.service` がルーターのソケット作成後にコンテナを再接続します。WebはUSB経由のローカル管理用です。閲覧専用サイトや公開リンクは既存の明示的な公開操作で使い、今回新たにインターネット公開はしていません。

2026-10-09更新: MCU書き込みは共通の `flash-mcu.sh` を使い、「Web停止 → ルーター停止確認 → 書き込み → ルーター起動・ソケット待ち → STM32リセット → Web起動」の順に行います。停止・書き込み・リセットが失敗した場合はそこで終了し、成功扱いやWebの自動再開をしません。UARTが固まってルーターを停止できない場合はLinuxを再起動してから再試行します。2026-10-09に実機で確認済み（同一イメージ・新イメージとも、約18秒で全段階通過）。

`ecocapture-mcu-supervisor.service`（`mcu-supervisor.py`、rootで常駐、導入は`install-mcu-supervisor.sh`）は、`/api/status`の`connected`が30秒以上falseのままなら「Web停止 → ルーター再起動 → NRSTリセット → Web起動」でMCUとの通信を戻します。起動後120秒は監視せず、書き込み中（`flash-mcu.sh`実行中）とWebに届かないときは何もしません。復帰は120秒に1回まで、3回続けて戻らなければ10分おきに下げます。MCUの内部リセット（ループ監視など）後に通信路が戻らない問題への対処で、2026-10-09にループ停止試験で停止から48秒での自動復帰を確認しました。

2026-10-13補強: 復旧は `flash-mcu.sh --recover` へ集約し、ファーム更新と同じ `/run/lock/ecocapture-mcu.lock` の `flock` を取得します。競合中は終了コード75で操作を延期し、復旧失敗回数に含めません。ルーター停止確認→起動待ち→NRSTリセットの順序は更新時と共通です。`connected` が明示的な真偽値でないAPI応答は監視不能として扱います。Web停止後の復旧失敗は自動でWebを再開しないため、journalを確認して手動復旧します。この補強版の実機適用・復旧時間測定は未実施です。

Windows更新は、既に動いている監視サービスをファイル転送後に再起動してから更新します。停止中のサービスは起動・有効化しません。手動配置では監視サービスを再起動し、古い監視プロセスを残したまま新しい更新手順を使わないでください。診断資料は `python3 mcu_diagnostics.py --output <保存先>.json` で採取できます。ttyHS1やGPIOを操作せず、TTYカウンタ、GENI/UART関連のカーネルログ、ルーター状態・journalを保存します。詳しい返答は `lintaroh_answer_20261013_2.md`。

`Update-UNOQ.ps1 -Firmware` は上書き前のUNO Q上のソースを `~/ecologger-source-backups/` とPCの `other/uno_q_tools/source-backups/` に保存します。これはソースの退避で、稼働中フラッシュの読み出しではありません。ソースの照合は `firmware/ecologger_v2/compare_sources.py`、ビルドイメージの静的領域の集計は `audit_image.py` を使用します。詳しい返答と統合条件は `lintaroh_answer_20261009.md`。

診断結果と現在の検証範囲は `outputs/logger_v2_bench_20261001/production` を参照してください。

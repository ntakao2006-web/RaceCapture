# EcoCapture 0.3.7

EcoLogger専用の日本語表示アプリです。Windows x64を主対象とし、Godot .NET / C#で実装しています。UIは白・黒を基本に、警告と経路だけ赤で表示します。

## Windowsで使う

UX250h（MZAH10）の2026-09-05試験向け更新は [UX250H_TEST.md](UX250H_TEST.md) を参照してください。
OBD要求は **Settings → 車両データ取得** で明示開始し、本体へ保存します。舵角は受信専用・実車照合前です。車種選択だけでは送信を開始しません。

1. ZIPをフォルダーごと展開します。
2. RaceCaptureなど、EcoLoggerのUSBを使用するアプリを終了します。
3. EcoLoggerのネイティブUSBを接続し、`EcoCapture.exe` を起動します。
4. 最初は「車載CAN接続なし」です。Homeから画面を選びます。

**`data_EcoCapture_windows_x86_64` はEXEと同じ場所に置いてください。EXEだけの移動では動きません。** .NETの追加インストールは不要です。Windows用の署名証明書は付けていません。

書込み機CH9102のポートはアプリの接続対象にしません。USB番号が変わっても自動で探し直します。接続待ちは正常な状態で、センサ未接続や欠測は `--` と表示します。値が受信できなくなったとき、古い値を現在値として表示し続けません。

## 画面

| 画面 | 内容 |
|---|---|
| Indicate | センサ値の一覧。標準は数値のみ・3列。「センサ状態」タブに更新頻度、接続、校正、記録欠落などを分離 |
| Race | 現在ラップ、速度、トータル、ベスト、前回ラップ。CANありの場合は回転数も表示 |
| Maps | 現在位置のマーカーを中央に固定。北が上のワイド地図だけが移動。標準横1 km |
| Solve | EcoLoggerのSDから走行CSVを取得。経路、平均・最高速度、距離、時間を表示 |
| Settings | 車体、表示項目、地図とIMU、水平補正、ラップ計測、接続と保存、ライブ共有 |

キーボードは `1`〜`5` で画面切替、`Esc` でHome、`F11` で全画面です。数値入力中は画面切替をしません。デモはHomeの「デモで試す」から明示的に開始し、画面上にDEMOと表示します。

### 車体と表示

- スーパーカブ／リトルカブ：速度、回転数、油温、ヘッド温度など。
- マツダ ロードスター：速度、回転数、水温、油温、油圧など。
- レクサス LX：速度、回転数、水温、負荷、姿勢など。
- 車載CAN接続なし：GNSS速度、標高、緯度、経度、前後・左右・上下加速度、ロール、ピッチの9項目。GNSSとIMUを分けて連続表示します。

車種は**表示プリセット**です。年式別CAN IDや換算式を推測して書き込む機能ではありません。EcoLoggerが実際に配信するチャンネルだけを表示し、未受信項目は `--` になります。カブの外付け温度・回転センサも、対応するロガー側チャンネルが必要です。ユーザー追加CANチャンネルの編集は今回の対象外です。

「表示項目」で各項目の表示／非表示、数値のみ／バー付き、小数桁、任意の上限警告を選びます。警告は色ではなく「上限超過」の文字です。表示設定は車種ごとに保持します。GNSS／IMU／CANの表示を無効にしても、本体のセンサやSD記録は停止しません。X/Y/Zはセンサ座標です。

### Race

「計測開始」でトータル時間を開始します。「手動ラップ」で周回を区切り、「計測停止」で結果を保存します。USBが切れても時計は止まりません。

自動ラップはSettingsでライン中心の緯度経度、**通過する向き**（北0°、東90°）、全幅、最短ラップ時間を指定します。ラインは指定方向と直角に置かれます。最初の通過で1周目を開始し、その次の通過からラップが記録されます。待機中の「手動ラップ」は1周目の開始操作です。計測中はラップ設定タブをロックします。

測位精度が25 mより悪い場合、通信に1秒より長い空白がある場合、逆方向やライン幅の外側を通過した場合はラップとしません。IMUだけの推定位置ではラップを判定しません。結果は約5秒ごと、およびラップ確定・停止時にPCへ保存します。USB再接続直後の位置飛びをラップに数えません。

### MapsとIMU

表示範囲は横0.5 / 1 / 2 / 4 / 8 kmです。淡色地図／標準地図を白黒で表示します。取得済みタイルは一時保存し、通信がない場合は古いキャッシュも利用します。

初期状態ではGNSSのみを使います。IMU補完を使う場合は、取付方向に合わせて車体前方／上方の軸を指定し、確認のチェックを入れてください。同じ軸は選べません。GNSSで進行方向を得てから、重力除去加速度と角速度で最大3秒の欠測を補います。取付軸の変更で補完は無効に戻ります。

ロガーとGNSSアンテナの取付位置を固定し、車体を停止・水平にして「現在を水平として校正」を実行すると、EcoLoggerへ車体座標の3×3補正行列とロール／ピッチのゼロ点を保存します。以後のCSVには補正済み5チャンネルが入り、同じCSV区間のメタデータに行列、ゼロ点、計算式も保存されます。校正値を変更した時点でCSV区間を切り替えます。

### Solve

「走行データ選択」でSDのCSVを選ぶと、USB OTG経由でPCへ分割取得して「経路」を開きます。赤い軌跡にカーソルを合わせると速度、前後・左右加速度、経過時間を表示します。ホイールでカーソル中心の拡大縮小、中または右ドラッグで表示移動します。

PNG / JPEG / WebP / BMP / SVGを最大8枚まで画像レイヤーとして追加できます。画像は白黒化して軌跡の背面に表示し、左ドラッグ、縮尺、回転、透明度でコース図面に合わせます。

これは経路案内や長時間の慣性航法ではありません。静止時やGNSSだけでは方位を確定できない状態では補完しません。「精度目安」は保証値ではありません。実走行での精度・自動ラップの検証は未実施です。

### ライブ共有

Settingsの「ライブ共有」は、①共有リンクを作ってコピー、②データ共有をON、③ブラウザで確認、の3操作です。共有相手はコピーされた `https://ecocapture-live.web.app/?id=...` を開くだけで、アプリの導入やFirebaseへのログインは不要です。EcoCaptureが受信した速度・位置・加速度・車両値を1 Hzで送り、明示的に開始したデモの値も `DEMO` 表示付きで共有できます。通信が一時的に切れた場合は最大約1時間分をメモリで待機し、復帰後に順次送ります。アプリを終了すると未送信の待機分は破棄されます。

送信を有効にしてもEcoLoggerのSD記録は変更しません。サーバー障害や無料枠超過時もUSB表示とSD記録は継続します。デモ値は実測値と混同しないよう、Web画面で `DEMO` と明示します。

緯度・経度は自宅、保管場所、移動履歴を推測できる情報です。キー登録はありませんが、共有リンクを知る相手は走行位置を閲覧できます。リンクは内輪だけで共有してください。

無料枠向けのスマホ画面と配備手順は [cloud/README.md](cloud/README.md) にあります。公開先URLは配布ビルドへ組み込むため、利用者がFirebase URLを入力する必要はありません。

## 保存先

Windows標準：`%APPDATA%\EcoCapture`

- `settings.json`：設定。変更時に自動保存。
- `sessions`：実測ラップのJSON / CSV。
- `demo-sessions`：デモ結果。実測と分離。
- `map-cache`：地図タイル。起動時に目安128 MiB以内へ整理。
- `solve-data`：SolveでSDから取得した走行CSVと付随メタデータ。
- `settings.json`のライブ共有欄：共有のON/OFFと、共有リンクに含まれるランダムなID。リンクは内輪だけで共有してください。

Settings「接続と保存」から保存先を開けます。

## 互換性と移植

既存のEcoLogger用RaceCapture互換JSONプロトコルを維持し、水平補正とSD読出しのコマンドを追加しています。既存チャンネル番号は変えず、補正チャンネルを末尾に追加しています。RaceCaptureへ戻す場合はEcoCaptureを終了してから起動してください。

Linux ARM64の実行ファイルも生成しています。Windows、Web閲覧、Linux ARM64の要件は [SYSTEM_REQUIREMENTS.md](SYSTEM_REQUIREMENTS.md)、Linux共通事項は [LINUX.md](LINUX.md)、Raspberry Pi 4Bへの最短導入手順は [RPI4_SETUP.md](RPI4_SETUP.md)、再ビルド手順は [BUILD.md](BUILD.md)、確認できた範囲は [VERIFICATION.md](VERIFICATION.md) を参照してください。

実機試験は静止した卓上環境で行っています。運転中に設定を操作せず、安全な場所で停止して操作してください。

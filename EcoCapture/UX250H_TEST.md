# UX250h / MZAH10 実車試験準備（2026-09-04）

対象は使用者提示の `MZAH10-AWXBB(F)`。レクサス公式諸元表の `MZAH10-AWXBB` は **UX250h・2WD** であり、LXではありません。括弧のFだけでグレードや年式は確定しません。既存LX表示プリセットは別物として残しています。

今回のファーム識別：`logger-v1-ux250h-obd-20260905a`。アプリ：EcoCapture 0.3.7。
**ロガーが手元にないため未書込み・未実車検証です。ソフトウェア試験の合格を実車対応の証明にはしません。**

## 明日の最短手順

1. **停車して**作業する。ロガー電源・配線・PCを固定し、換気を確保する。運転者は画面操作しない。
2. ファーム更新は車両OBDから外した状態で行う。稼働中のSDは既存の `sd_control.py eject` で `safeToRemove=true` を確認してから電源を扱う。GNSS OTP設定ツール・SDフォーマット・Flash全消去は実行しない。
3. 配布ファームの `flash.ps1` をA105の現在のCOM番号を指定して実行する。CH9102とネイティブUSBのポートを取り違えない。既存の `logger_v1` パーティション配置専用。
4. EcoCapture 0.3.7のZIPを**新しいフォルダーへ**展開して起動する。表示用USBはロガーのネイティブUSB。A105だけではEcoCaptureの自動接続対象にならない。
5. OBDをATA6561/J5側へ接続する。既知の配線と終端抵抗未実装を維持する。他の診断器は同時に要求送信しない。
6. Settings → **車両データ取得** → **UX250hの取得を開始・本体へ保存**。画面のファーム名も照合する。これでUX表示へ切替わる。車体のプルダウン選択だけでは送信開始しない。
7. 要求受付数だけでなく**応答数**が増えること、回転数・車速・水温・電圧などが更新されることを確認する。初期の対応PID調査に数秒かかる。無応答なら最大約30秒で状態を記録し、要求送信を停止して確認する。
8. HYBRID/READY中にエンジン停止すると、正しい応答は **0 rpm**。取得できない値は **--**。GNSS速度は `GPSSpeed`、OBD車速は `Speed` で、互いの欠測を埋めない。
9. 舵角のフレーム数を確認する。安全に停車した状態で、無理な据え切りや端当てを避けて左右・直進を照合する。符号、概ねの角度、直進付近、250 ms以上の更新断で欠測になることを確認する。**照合前の舵角は運転判断に使わない。**
10. GNSS測位・SD記録・欠落数が正常なら短時間走行から開始する。その後30分、数時間へ延ばす。安全な停車時にCANエラー・SD欠落・再起動・更新停止を確認する。
11. スマホ共有は任意でON。地理院地図に赤い経路が重なり、DEMOと実測が区別されることを確認する。
12. 終了時は **要求送信を停止・受信専用に保存**。SDを安全に閉じてから外す。設定は本体保存なので、開始状態のままならUSBを外してもOBD要求は継続する。

## 取得できるものと条件

| 項目 | 取得方法 | この版の扱い |
|---|---|---|
| 回転数 / 車速 | Mode 01 PID 0C / 0D | 対応確認後に要求。最大目安4 / 2 Hz（他要求・応答待ちで低下） |
| スロットル / 負荷 | PID 11 / 04 | 最大目安1 Hz。アクセルペダル位置とは別の値 |
| 水温 / 吸気温 / ECU電圧 | PID 05 / 0F / 42 | 最大目安0.5 Hz |
| 油温 | PID 5C | 最大目安0.33 Hz。過去のUX調査で応答あり。ただし今回も対応ビットを確認 |
| 舵角 | Toyota系 `0x025` の受信 | 公開定義適用・実車照合前。OBD端子で見えなければ `--` |
| 位置 / GNSS速度 / 加速度 | ロガーのGNSS/IMU | 既存経路。SDは100 Hzスナップショット、PC表示は最大10 Hz |

### OBDの実装

- CAN1 = 11 bit Classical CAN・500 kbps。**新規設定の既定は受信専用**。明示開始後だけnormal modeでACKと要求送信を行う。
- 読取専用のMode 01だけ。対応PID 00/20/40を確認してから、広告された8項目だけを要求する。
- まず0x7E0/0x7E8。無応答が3回なら0x7DF機能アドレスで探索し、RPM対応を広告したECUへ固定する。複数ECUの温度等を混ぜない。
- 最大10要求/秒・同時1要求・応答待ち250 ms。無応答PIDは間隔を伸ばし、通信断後は低頻度探索へ戻る。
- 送信はsingle-shot。自動再送を繰り返さない。CAN bus-offまたは送受信エラーカウンタ96以上で停止し、受信専用へ戻す。自動で送信再開しない。停車・確認後の明示開始が必要。
- 「要求受付」は送信キュー受付数であって、車両への到達証明ではない。生CAN CSVの `TX_REQ` も同じ意味。必ずRX応答と照合する。
- 既存設定とIMU校正は保持し、車両取得設定だけを別NVSキーへ保存する。旧NCロードスター固定デコードはOBD/UX設定中には使用しない。既存カスタムCANマッピングは残るため、別車両用の設定がある場合は事前確認する。
- 29 bit OBD、250 kbps、CAN FD、UDS拡張診断はこの版の対象外。エンジン停止値は有効、通信断は欠測。

### 舵角の根拠と未検証範囲

[opendbcのToyota車両対応表](https://github.com/commaai/opendbc/blob/master/opendbc/car/toyota/values.py) はLexus UX Hybrid 2019–24を `TOYOTA_COROLLA_TSS2` 系へ割り当てています。
[Toyota nodsu DBC](https://github.com/commaai/opendbc/blob/master/opendbc/dbc/generator/toyota/toyota_nodsu_pt.dbc) が取り込む
[Toyota共通DBC](https://github.com/commaai/opendbc/blob/master/opendbc/dbc/generator/toyota/_toyota_2017.dbc) の0x025は、signed 12 bit ×1.5°とsigned 4 bit ×0.1°の和です。
[車両状態の実装](https://github.com/commaai/opendbc/blob/master/opendbc/car/toyota/carstate.py) もこの和を使います。本版は文献上の±500°範囲を超える値とfractionの予約値を拒否します。STEER_RATEは係数未確定の注記があるため追加しません。

これは**ADAS側CANの定義であり、OBD端子での可視性を保証しません**。このリポジトリの2026-08-06 UX調査では0x025を観測していません。舵角が来ないからといって、推測した診断DIDの総当たり、セッション解除、ゲートウェイ回避、操舵制御命令は送りません。明日の生ログで可視性を判定します。

ハードウェアループバック合格は送受信経路の検証です。車両のゲートウェイ、公開信号、ID/係数まで証明するものではありません。[ESP32-S3 TWAIはCAN FD非対応](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/twai.html) です。

地図タイルは閲覧端末から国土地理院へ直接アクセスします。地図範囲/IPは地図配信先へ伝わりますが、共有IDを含むURLはRefererとして送らない設定です。位置共有は従来通りOFFが初期値です。
共有をONにしたコピーは引き続き同じ `ecocapture-live` Firebaseプロジェクトの枠を消費します。今回アカウント認証・課金設定・データベースルールは変更しません。共有リンクを知る人は閲覧だけでなく書込みも可能な現在の制約があります。

## デモと検証境界

UX250hプリセットのデモにはEV走行時の0 rpmとエンジン稼働を含め、合成舵角も同じUSB/共有データ契約へ流します。実車のステアリング比を校正したシミュレーターではありません。実機の欠測から自動でデモへ切り替わることはありません。

この版は82ベースチャンネルです。通常起動時のschemaは84が目安ですが、GNSS再設定・カスタムチャンネル追加でrevisionは変わり得ます。受信側は実機のmetaを正として追従します。

保存すべき明日の結果：ファーム識別、取得設定、CAN要求/応答/エラー、舵角受信数、SD行数/欠落、起動からの時間、`*.csv` / `*_can.csv` / `*.meta.json` / `*.end.json`。生ログは位置情報を含むためGitや公開共有へ自動投入しません。

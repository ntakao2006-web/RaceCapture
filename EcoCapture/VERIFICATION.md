## USB復帰とSD保護

接続処理単体を実EcoLoggerに45秒つなぎ、診断コマンドでネイティブUSBだけを3回外しました。

- 初回を含め4回接続、367サンプル受信、全367サンプルでIMU/SD正常。
- 不正フレーム0。約2.0〜2.6秒で受信復帰。
- SD記録は4,630行増加。SD欠落、SDエラー、IMUエラーの増加なし。
- 本体再起動なし。CAN listen-onlyを維持。

EXEのUI試験でもRace表示中にUSBだけを1回外し、計測が続くことを確認しました。デモ往復と手動再接続も確認しています。検証用UART操作は `testUsbReconnect` の `LOGGER_USB_ONLY` に限定しました。

最終配布EXEの37項目試験では、SDが3,943行増加し、SD欠落／SDエラー／IMUエラーの増加なし、本体再起動なし、CAN送受信なしでした。試験中だけ水平補正を有効化し、終了時に無効・単位行列へ戻したことも読戻しました。

これは電源を落とさないUSB detachの試験です。物理的な電源断、Windowsのスリープ復帰、ケーブルやハブ固有の障害までは確認していません。

## 性能と配布物

Windowsでの通常表示時の実測は `artifacts/runtime-performance/performance.json`、EXE全画面試験時の実測は `artifacts/exe-ui-accepted/verification.json` に保存しました。メモリ値にはGodotと同梱.NETが含まれます。CPUは論理1コアを100%とした値で、マシン全体の使用率ではありません。

各画面で5秒待機後、静止状態を約20秒測定しました。メモリは各プロセスの起動を含むピークWorking Setです。

| 画面 | メモリ | 通常表示のCPU（1コア比） |
|---|---:|---:|
| Home | 278.5 MiB | 4.3% |
| Indicate | 282.9 MiB | 7.2% |
| Maps | 284.2 MiB | 6.4% |

全画面切替、Solve取得・解析、デモ、地図取得、画面撮影を含む最終UI試験ではピークWorking Set 393.3 MiBでした。これは短時間の卓上測定で、長時間走行時の最大値を保証する数値ではありません。

設計は4 GB RAMを前提とし、受信履歴・地図取得・描画負荷を制限しています。詳細は [LINUX.md](LINUX.md)。Windowsでの性能をARM機の性能保証には使いません。

Windows x64 EXEと同梱ランタイム、Linux ARM64のELFと同梱ランタイムを出力しています。Linux ARM64はビルドと形式確認までで、Pi 4 / ROCK 5B上では未検証です。

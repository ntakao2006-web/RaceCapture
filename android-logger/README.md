# EcoLogger（Androidアプリ）

エコラン大会でVer.2ロガーを積まない車（スマホ組）用。**主に二輪・EV二輪クラスで使う**（四輪の規定も選べる）。Android端末の内蔵GNSS・IMUを0.1秒ごとの行にそろえ、
**端末内にCSVで記録**しながら、Ver.2ロガーと同じ形式で`ecorun-logger-server`へ送る（`task_ecorun_20261024_breakdown.md` ER-11）。
画面を消しても常駐通知を出して動き続ける。音声は入っていない（大会では同じスマホでDiscordの通話を並行して使う）。

## 使い方

画面は**横向きのドライバー用**。左に速度を大きく、右に「周回（何周目／規定周回）」「残り時間（規定時間まで）」
「この周の目標 平均km/h」「この周の平均 km/h」、上に記録・GNSS・送信・電池の状態。
エコランは平均速度で走るので、下の2枚は平均速度で出す（`Pace.kt`）：
計算はチームの記録表（`Honda エコ マイレッジ チャレンジ　本番用記録表.xlsx`）と同じ：目標タイム（規定時間−余裕）を距離に比例して各周の終わりの「目標タイム」に割り振り、遅れ・貯金をその次の1周で取り返す。
- **この周の目標**：この周の距離 ÷（この周の終わりの目標タイム − ここまでの実走タイム）＝記録表の「次目標速度」。周の始まりに決まって周の間は動かない。2周目からは下に「差」（目標タイムに対する貯金、＋が早い）と「前半」（遅れを前半の半周で取り返すときの速さ、記録表の「次半周目標速度」。後半は計画どおりの速さで走る）
- **この周の平均**：今走っている周のここまでの平均（走るにつれて変わる）。下に目標との差。記録表の色分けに合わせて、目標未満は赤「遅い」、目標〜目標+1km/hは緑「目標どおり」、それより上は黄「速すぎ」。周の始まり5秒は「計測中」
- 1周の距離は規定距離から出す。スタート→コントロール、ゴール→コントロールのラインの間隔だけ最初の周・最後の周を短くし、残りを周回数で割る。周の途中の平均はGNSSの速度を積算した距離を、前の周の規定距離との比で補正したもの
- **余裕**：規定時間ちょうどを狙うと数秒の遅れで失格になるので、規定時間より「余裕（秒）」だけ早くゴールする目標で目標・貯金を出す（設定の「大会」、**クラスごとに別の値**を保存、既定30秒）。残り時間の欄の下に「余裕30秒」と小さく出る。残り時間の欄は本当の規定時間までのまま
- **大会の設定のロック**：クラス・規定周回数・規定時間・規定距離・余裕は、設定の「大会の設定をロックする」で固定できる（ラインのロックとは別）。外すのは長押し＋確認。「ラップをリセット」でラインと一緒に自動でロックされる
- 規定距離が無い（手入力クラスで空欄）ときは、従来どおりラップタイムと目標ペース（時間）で出す

記録中は画面が点いたままになり、ロック画面の上にも出る。設定の「画面」で、記録していなくても画面を消さない（既定オン）・記録中は最大の明るさ（既定オン）を選べる。ほかのアプリ（Discordなど）を前に出すとそのアプリの設定で暗くなるので、走行中はこのアプリを前に出しておく。

1. 「設定」で、車の名前、主・予備サーバーのURL（`wss://<ホスト>/ws/audio/<room>`、roomは車ごと）を入れて保存し、**クラス**を選ぶ（2026年全国大会の競技規則の名前。今年のチームの3クラス＝`CNG3` CNグループⅢ（高専CN燃料）・`CN二輪` CN二輪車クラス・`EV二輪` 電動二輪車クラスが先頭で、ほかにCNG1・CNG2・CNG4・CN2人乗り・手入力。CNグループⅠ〜Ⅳは7周・39:20.11、CN2人乗り・CN二輪車・電動二輪車は3周・16:27.36（競技規則 第2章第1条第1項4））。「点検」で電池の最適化を外す
2. 「● 記録を始める」→ 位置情報（正確な位置）と通知を許可する
3. ライン：最初から**全国大会（もてぎ）のおおよその位置**が入っている（Googleマップから拾った値。3本とも西側の直線上で、北からゴール・コントロール・スタート。反時計回り＝ここでは南向きに走るので向き150°、ずれを見込んで幅40m）。コースウォークで記録を始めてから、ライン上に立って「現在地にする」で正確にする（または地図で調べた「緯度, 経度」を入れる）。設定の「もてぎ（全国大会）のおおよその位置に戻す」で戻せる
4. 本番の前に「ラップをリセット」
5. 走り終えたら「■ 長押しで停止」（触れただけでは止まらない）

- 記録ファイル：端末の`Download/EcoLogger/EL_<車の名前>_<日時>.csv`（USBでPCにつなぐと見える。アプリを消しても残る）
- 通信が切れている間も記録は続く。送信は「今」の値だけで、切れていた間の分を後から送り直すことはしない
- 主サーバーにつながらない・切れたら、間を空けずに予備へ移る。予備へ移った後は、予備が切れるまで主へは戻らない（Ver.2ロガーと同じ）
- ラップ判定はVer.2ロガー（`EcoCapture-Web/lap.py`）と同じ（スタート・コントロール・ゴールの3本、規定周回の前はゴールを無視、線から幅以上離れるまで次を数えない）。
  違いは、スマホの測位は10〜25mずれることがあるので、①ラインの幅の半分に**その測位の精度（最大25m）を足した**範囲を通過とみなす、②精度が25mより悪い測位は使わないが、前後の良い測位どうし（10秒以内）を続きとして扱い、ラインをまたいだかを見る、の2点（2026-10-22の試走でスタートラインを2回とも取りこぼしたため）。ラップの状態は端末に保存され、アプリを開き直しても続く

## 送る値

`podium.meta`のチャンネル名・単位・桁数は`EcoCapture-Web/podium.py`に合わせてある（`Latitude`・`Longitude`・`GPSSpeed`・`Utc`など）。

- `Utc`：GNSSの時刻（端末の時計は使わない）。1Hzの測位の間の行は、測位からの経過時間を足して進める
- `GPSFix`：3＝高度つきの測位、2＝高度なし、0＝3秒以上測位が無い
- `GPSSats`：測位に使っている衛星の数
- `AccelX/Y/Z`（m/s²、重力を含む）・`GyroX/Y/Z`（°/s）：**端末自身の軸**（画面を正面に見て、右がX、上がY、画面から手前がZ）の0.1秒間の平均
- `LongAccel`・`LatAccel`・`VertAccel`（G）：**取付けの向きを校正した車の軸**（`Mount.kt`）。＋は加速・車の右向き・上向き（止まっていると上下が約1G）
  - 上下（1G校正）：止まっている間の加速度の平均を「上」とする。記録中にGNSSの速度が1km/h未満で2秒揺れなければ自動で取る（付け直して10°以上変わったら取り直す）。
    設定の「今の向きで1G校正」で手動でも取れ、手動で取ったものは自動では上書きしない（向きが変わったら設定画面に出す）
    **二輪クラスでは停車中の自動校正をしない**（サイドスタンドや足つきで車体が傾くため）。代わりに、まっすぐ一定の速さで走っている1秒区間（向きの変化2°/秒未満、加減速0.2m/s²未満）の平均を10区間以上ためて「上」とする（走行中の車体は平均すると立っている）。手動校正は車体をまっすぐ立てて行う
  - 前方：最初は「画面がドライバーを向いている＝端末の背面が前」と仮定。走り出すと、まっすぐ走っている間の測位ごとの速度の増減（GNSS）と同じ区間の水平の加速度を掛け合わせて足し込み、十分たまったら（0.5m/s²の加減速で十数回分）それを前方とする
  - 校正は端末に保存され、設定の「校正をやり直す」で消せる

ラインを設定するとラップの値（`LapCount`・`CurrentLap`・`LapTime`・`BestLap`・`ElapsedTime`・`RaceTime`・`LapsLeft`、時間は分）も送る。CSVは上の値に、測位の精度`Accuracy`（m）を足したもの。

## ビルド

Android Studio（同梱のJDK）とAndroid SDK（platform 36・build-tools 36）が必要。`local.properties`の`sdk.dir`はPCごとに書く（Git管理外）。

```bash
cd android-logger && JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew testDebugUnitTest assembleDebug
```

APKは`app/build/outputs/apk/debug/app-debug.apk`。端末へは`adb install -r`で入れる。

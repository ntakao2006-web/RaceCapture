# ドライバーの声の無音判定（ER-10-9）

ドライバーはボタン無しの常時接続なので、ロガーが「声が出ている間だけ送る」を判定する。
判定はRNNoise（xiph、BSD）の「声らしさ」（10msごと、0〜1）で行い、`voice_gate.py`の`VoiceGate`が
開く（2フレーム連続で0.6以上）・前100msを付けて送る・声が途切れて400ms後に閉じる、を受け持つ。

## RNNoiseは旧版（v0.1.1）を使う
最新版（v0.2、2024年のモデル）は重く、UNO QのCPU（Cortex-A53）では実時間に間に合わない。
自宅サーバー（RK3588）で、10msの音を処理する時間をC言語で測った結果（2026-10-15）：

| 版 | Cortex-A76（速いコア） | Cortex-A55（UNO QのA53に近い遅いコア） |
|---|---|---|
| v0.2（最新） | 2.3 ms | **11.4 ms（実時間に間に合わない）** |
| **v0.1.1（旧版）** | 0.19 ms | **0.8 ms（1コアの約8%）** |

ビルド（autoconf不要）：
```
git clone https://github.com/xiph/rnnoise.git && cd rnnoise && git checkout v0.1.1
gcc -O2 -fPIC -shared -Iinclude -Isrc -o librnnoise_old.so src/denoise.c src/rnn.c src/rnn_data.c src/pitch.c src/kiss_fft.c src/celt_lpc.c -lm
```
Pythonから1フレームずつctypesで呼ぶと、呼び出しのたびのコピーで速いコアでも約0.1ms余分にかかる。
UNO Qに載せるときは、判定の部分をCで書くかnumpyの配列をそのまま渡す形にする。

## 試験（`gate_test.py`）
PCの音声合成（Haruka）で作った無線の短文6本を、合成した車内の騒音（エンジン80Hz＋倍音・ロードノイズ・風切り）の上に
120秒の中で散らして置き（声は全体の12.3%）、騒音の大きさを3段階に変えて測った（2026-10-15、旧版）：

| 騒音 | 声との差 | 送った時間 | 声を送れた割合 | 声の無い所で送った割合 | 声から1秒以上離れた所での誤送信 |
|---|---|---|---|---|---|
| 静か | 21dB | 21.3% | 99.5% | 10.3% | **0.0%** |
| 大きい | 11dB | 20.5% | 99.1% | 9.5% | **0.0%** |
| とても大きい | 3dB | 20.1% | 98.6% | 9.1% | **0.0%** |

「声の無い所で送った割合」は、ほぼすべてが語の切れ目と語尾の後の保持（400ms）。
比較した単純な音量判定（騒音の底から+6dB）は、ロードノイズのゆらぎで**99.8%送りっぱなし**になり使えない。
送る時間が全体の約2割なら、ドライバーの上りは垂れ流しの約1/5（1時間で約1〜1.5MB）。

## UNO Qで実時間に回す（`voice_gate_live.c`、2026-10-17）
`arecord`の生PCMを標準入力で受け、`voice_gate.py`の`VoiceGate`と同じ規則で判定するC版。1秒ごとに処理時間・声らしさ・開いていた割合を出す。
ビルドと実行はファイル先頭のコメントのとおり（RNNoiseはUNO Q上で`git clone`して`v0.1.1`）。

| 条件 | 10msあたりの処理 |
|---|---|
| 録音済みファイルを一気に流す | 平均0.83ms（10msの8%） |
| USBマイクからライブ20秒 | 平均2.18ms・最大4.02ms（22%） |
| ライブ40秒＋カメラ焼き込みを同時 | 平均1.76ms・最大4.59ms（18%） |

ライブのほうが遅いのは、待ち時間の多い処理でCPUのクロックが下がるため（`schedutil`）と思われる。いずれも10msに十分間に合う。
研究室で人の話し声を拾うと声らしさは1.0まで上がり、ゲートが開いた。**静かな時は0.02止まりで開かなかった**。

**注意**：騒音は合成で、声は音声合成のきれいな声。実車の騒音・ヘルメット越しの声では違う可能性がある。
UNO QにUSBオーディオがつながったら、実車で録音して同じ試験をする。

## LTEで音声の上り下りを試す（PCから外して、`lte_voice_test.sh`、2026-10-19）
UNO QはPCのUSBから給電されているので、外へ持ち出すと再起動する。そこで、電源投入時に1回だけ走らせる
（`@reboot sh …/lte_voice_test.sh <中継のURL> 120`、URLはリポジトリに書かない）。
仕掛けは最後まで走ってから消える（`lte_voice.done`を残す）。バッテリーをつないだ瞬間の数秒の起動で使い切らないため。
音声なし→下りのみ→上り（話しっぱなし）→上り（4秒話す・6秒黙る）→双方向を各120秒測り、最後に送信設定と本物の音声エージェントを元に戻す。

- `fake_agent.py`：マイクの代わり。録音済みの声（8kHz）を音声エージェントと同じ形（Opus 6kbps・120ms）で出す。ピットの声は数えるだけで鳴らさない。
- `pit_loop.py`：ピット役。自宅サーバー上で同じroomに入り、声を流し続けて、ロガーの声が届いた数を数える（numpy不要）。
- `telemetry_rate.py`：ロガーの状態APIから、5秒ごとの件数/秒と音声のカウンタを出す。
- `burst_talker.py`：LTEのロガーと同じく、120msの声を4個（0.5秒分）ずつまとめて中継サーバーへ送る。`pit_loop.py`と並べて、まとまって届く声をサーバーが捨てないかを確かめる（2026-10-19、中継サーバーの修正の確認に使った）。

- `boot_to_lte.sh`：送信設定をLTEにしたまま電源を入れ、カーネルの起動からの秒数で、最初のテレメトリまでを2秒ごとに記録する（`@reboot`で1回、2026-10-20）。

ドライバー役の声は、ユーザーが無線の短文を読み上げた29秒（UNO Qの`~/audio_check/driver_read.wav`、本人の声なのでリポジトリには入れない）。
以前の`driver_reply.wav`は補正前の録音（ピーク-30dBFS）で、声として聞き取れないので使わない。

結果は`task_ecorun_20261024_breakdown.md`のER-10-9（2026-10-19）。

# logger_v2 部品選定・GNSSアンテナ回路の確認

更新：2026-09-20。対象は現時点の `logger_v2.kicad_sch` と `logger_v2_lte_sd.kicad_sch`。

2026-09-21追記：本書の旧案部品を残す方針は、ユーザーの整理指示により更新した。旧案3個を削除し、必要な28個を未配線で追加済み。最新の配置・調達一覧は [部品配置更新_20260921.md](部品配置更新_20260921.md) を参照。本書の72個という集計とCSVは9月20日時点の記録。

## 採用内容

ユーザー指定のアンテナは **JCA002（秋月112223）**。GNSSはMAX-M10M-00Bを維持し、V2の外部3.3Vから抵抗・RFチョークを通す給電方式を採用する。V1のVCC_RF給電も通常動作としては成立するが、V1の10Ω抵抗はアンテナ給電に直列ではなく、短絡電流を制限する抵抗にはなっていない。

SDはV1と同じ **Molex 47219-2001** へ置換。シンボル、フットプリント、STEPをプロジェクト内に用意した。TE 2452796-1 SIMスロットは維持する。独立したSD挿入検出端子がなくなるため、将来のUNO Qピン割り当ては **21本使用・A5の1本が予備**。DAT3/CDはSPIのCSであり、機械式カード検出端子ではない。

ユーザー指定の「可能な限り秋月」「裸SMD優先」「DIP化基板を使わない、IMUのみ例外」を適用した。現在配置された72部品すべてに選定品番・調達先・備考を付与し、そのうち57部品の調達先を秋月とした。この数はDNPと旧案の未配線部品を含む配置数で、購入数ではない。LTE電源のL/Cなど今後設計する未配置部品を含む完成BOMではない。

個別属性は回路図の非表示フィールド `MPN / Supplier / SupplierCode / SupplierURL / SelectionNote` に保存。機械処理・照合用の一覧は [部品選定CSV](output/部品選定_20260920.csv)。未採番の追加部品はシート名とUUIDで識別する。

## 4. GNSS：V1とV2の違いと採用根拠

比較は実回路図から出力したネットリスト `output/v1_compare_20260920.xml` と `output/v2_compare_20260920.xml` に基づく。見た目ではなく端子の接続を確認した。

|項目|V1|今回のV2|
|---|---|---|
|アンテナ電源|MAX-M10MのVCC_RF、14番|外部3.3V。VCC_RFは未接続|
|DC経路|VCC_RF→27nH→SMA/RF_IN|3.3V→R7 27Ω→L1 27nH→SMA/RF_IN|
|容量・抵抗|VCC_RFからR47 10Ω→C34 10nF→GND|R7後の給電ノードからC1 10nF→GND|
|短絡電流|R47はバイパス枝なのでアンテナ電流を制限しない|R7がアンテナ給電に直列で電流を制限|
|LNA_EN|R49 10kΩでGNDへ|R10 10kΩをDNP、実質未接続|
|RF保護|該当RFネットに外付けTVSなし|D11低容量双方向TVSをSMA/RF_INからGNDへ|

**V1が通常受信できる構成であることと、短絡時まで適切に保護されることは別。今回はV2の外部給電＋直列抵抗を採用する。** u-bloxはVCC_RFまたは外部の低雑音電源からのアンテナ給電を認めている。VCC_RFの動作時最大供給電流は50mAで、JCA002の15mAは範囲内。データシートの絶対最大250mAを通常動作の設計値として使わない。

### 採用回路と計算

```
+3V3 ─ R7 27Ω/1W ─┬─ L1 27nH ─┬─ SMA中心端子 → JCA002
                   │            ├─ MAX-M10M RF_IN（11）
                 C1 10nF      D11 低容量TVS
                   │            │
                  GND          GND
```

- JCA002仕様：2.2～5V、5～15mA。根拠は [アンテナのメーカー仕様書](https://akizukidenshi.com/goodsaffix/JCA002_a.pdf)。
- L1はMurataの保存カタログで27nH、定格300mA、DCR最大0.46Ω、自己共振周波数最小1.7GHzを確認。ここでは300mAを保守的な検討値に使う。推奨シリーズ採用であり、異なるシリーズに対する「GNSS帯域で500Ω超」の条件を27nHの理想リアクタンスだけで判定したものではない。
- 最大負荷15mA時：`3.3 − 0.015×(27+0.46) ≈ 2.888V`。3.3V電源−5%、抵抗+5%を仮定しても約2.703Vで、2.2V下限を満たす。電源公差±5%は設計上の仮定で、UNO Qの実測値ではない。
- SMA短絡時：公称約122mA。電源+5%・抵抗−5%では `3.465/25.65 ≈ 135mA`、抵抗損失約0.468W。L1の300mA検討値を下回る。R7は70℃定格1W品とし、高温時のディレーティングとPCBの放熱を確認する。
- 通常15mA時のR7損失は約6mW。短絡時の連続約0.47Wは無視できないため、周囲部品・基板温度も確認する。これは受動的な電流制限で、短絡検出・自動遮断・故障通知ではない。
- RF_INには内部DCブロックがある。許容RF_IN DC電圧の範囲内でこの給電方式を用いるため、外付けの直列DCカットコンデンサーは必須ではない。RF_INの許容範囲は−5.5～+5.5V。ESD保護はDC耐圧の代わりではない。
- LNA_ENは出力。外部LNAや電源スイッチを制御しないこの回路では未接続でよく、10kΩのプルダウンは必須ではない。V1のR49があることを理由にV2のR10を実装しない。アンテナ本体をLNA_ENから直接給電しない。
- 外部3.3Vは低雑音であることが条件。LTE送信・SD書込み時の3.3V変動とGNSS受信感度を確認する。現構成ではGNSSの省電力状態でもアンテナは給電されたままで、開放/短絡を判別するアンテナスーパーバイザー機能も未実装。

一次資料は [MAX-M10M Integration Manual UBX-22038241 R02](refs/MAX-M10M_IntegrationManual.pdf) の3.3節、Appendix B/C（pp.28–30、84–89）、[MAX-M10M-00B Data Sheet UBX-22028884 R04](refs/MAX-M10M-00B.pdf) の端子・電気仕様（pp.9–12）。RF推奨値に従う回路検討であり、実基板での受信性能・ESD耐性を測定済みという意味ではない。

## 5. フットプリント・3D・検証

- SD：`logger_v2_expansion:Micro_SD_Card_Molex_47219-2001` と `logger_v2_expansion:Molex_47219-2001`。V1のフットプリントをそのまま移植。1～8番は信号接点、4か所の保持パッドは共通9番。
- V1のSDモデルはGit LFSの参照ファイルだったため、保存済みオブジェクトのSHA-256を照合して実体STEPを取り出した。V1自体は変更していない。V2に約2.8MBの `3dmodels/Molex_47219-2001.step` を収め、V1のオフセット・回転設定を維持して3D表示を確認した。
- U1：`logger_v2_custom:TC74HC595AF`、`Toshiba_SOP16_P300_1.27A`。本体5.3×10.3mm、端子外幅7.8mm、ピッチ1.27mmを東芝資料と照合。端子位置が同じシンボルへ差し替え、実装ランドはKiCadの幅広SOIC16の形状を基にした。3Dは公称寸法の簡易STEPで、メーカー提供品やリード曲面の厳密再現ではない。
- TC74HC595AFとSDを確認用基板に配置し、[3D表示](output/selected_footprints_3D.png) を確認。実プロジェクトのPCBへは転送していない。
- 全72配置部品について、シンボルの端子番号とフットプリントのパッド番号の一致、モデルの参照解決・STEP実体を確認。使用するSTEP 28種類はFreeCADで全て読込み・形状有効性を確認した（`output/selection_step_geometry.json`）。汎用モデルを含み、特にシールドヘッダーの長ピンとスタック高さは実物との照合が必要。
- 元回路図と比較し、配線・ラベル・接続点・未接続マーク・部品位置・UUID・DNP・採番状態が不変であることを確認。ルート回路図のネット接続も全件不変。IMUプルアップは実装、LNA_ENプルダウンはDNPを維持。
- ERCは変更前後ともルートの既存 `STATUS_LATCH` ラベル未接続1件。今回追加したERC違反はない。LTE/SDファイルは現在のルートに接続されていない独立した未配線回路図で、全機能の電気接続確認は未完了。
- [ルート図面](output/logger_v2_selection.png) と [LTE/SD図面](output/logger_v2_lte_sd_selection.png) を新規出力して確認した。[構造検証結果](output/selection_final_verification.json) に検証範囲を記録。

今回変更したのは品番・定数・対象シンボル/ライブラリと文書。PCB配線・製造データの更新、LTE/SD周辺回路の完成、実機同時動作試験は実施していない。バックアップは `logger_v2-backups/before_akizuki_selection_20260920/`。

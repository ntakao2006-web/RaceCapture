# スマホの予備画面をDASHに合わせた分の引継ぎ（2026-11-04）

SUGOの予備の車載画面（EcoLoggerアプリの「サーキット」、SG-2-8）を、EcoCapture DASH（SG-2-6）の11/4の警告の決まりに合わせた。
コードと試験はクラウドのセッションで済ませた。**APKを作る・画面を見る・スマホへ入れるのはPCでしかできない**ので、その手順をここに書く。

## 1. 合わせた決まり（DASHと同じ）

| 項目 | 決まり |
|---|---|
| 油圧の警告 | 回転数に対して油圧（`OilPress`、kPa）が低いとき。1500rpm未満は見ない。1500rpmで100kPa、3000rpm以上は200kPa（間は直線）を0.5秒続けて下回ったら出る |
| 温度の警告 | 今までどおり油温120℃・水温110℃を1秒続けて超えたら出る |
| 消えるとき | 5秒続けて戻ったら（3つとも同じ） |
| 同時表示 | 出ている警告を赤い帯の中に横に並べる（油圧・油温・水温の順。2つなら0.75倍、3つなら0.55倍）。単位は数字の後ろに小さく |
| 点滅 | 警告が出てから1分、明るい赤と暗い赤を1秒に2回切り替える（白い文字は消さない）。新しい警告が加わるとまた1分 |
| 警報音 | 2音の警報を1.5秒鳴らして0.25秒空ける、を6回（約10秒）。スマホの「アラーム」の音で鳴らす（今までどおり）。**11/5に音の中身を2500Hzの速い連打（0.05秒鳴らして0.05秒止める）に変えた**（長さ・区切りは同じ。ARCHITECTURE.md 4章の⑫） |
| 右下の表示 | 油圧が一度でも来たら「油温・油圧」（途絶えたら「油圧センサー途絶」など）。来ていないうちは今までどおり「油温センサー」 |

## 2. 変えたファイル

| ファイル | 変えたこと |

| `android-logger/.../CircuitView.kt` | 赤い帯に並べる・点滅（暗い赤`#520808`） |
| `android-logger/.../CircuitFeed.kt` | Ver.2の`dash`から`press`・`rpm`を読む |
| `android-logger/.../SettingsActivity.kt` | 説明の文と「警報音を鳴らしてみる（約10秒）」 |
| `android-logger/.../CircuitTest.kt` | 新しい試験5件（油圧の線・0.5秒・並べる・1分の点滅・右下の表示）。音の長さの試験を10秒に |
| `EcoCapture-Web/field.py` | スマホへ送る`dash`に`press`（`OilPress`）と`rpm`（`RPM`）を足した。試験は`test_field.py` |

## 4. PCでやること

> **2026-11-04 PCで4-1・4-2を済ませた**：Gradleのビルドと単体テスト86件が通り、エミュレーターで下の表の出方をすべて確かめた（結果は`task_sugo_20261108_breakdown.md`のSG-2-8、画像は`outputs/circuit_check_20261104/`）。残りは4-3・4-4（了承を取ってから）。

### 4-1. ビルドと試験

```bash
git pull   # ブランチ ccr-5a29e5b4-53o1ku（PR #1）
cd android-logger && JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew testDebugUnitTest assembleDebug
```

- テストが**86件**通ること
- 失敗したら：AGP 9.4.1に入っているKotlinとの違いが考えられる。上の表のファイルの、エラーが出た行を直す

### 4-2. エミュレーターで見る（前回と同じ`ecologger_test_9a`）

1. 作り物のロガーを立てる：`python outputs/circuit_check_20261104/circuit_mock.py`（5倍速）
2. エミュレーターでアプリを開き、サーキットで記録を始める（前回と同じつなぎ方）
3. `outputs/circuit_check_20261104/circuit_mode.txt`に1語書いて、出方を見る

   | 書く言葉 | 見ること |
   |---|---|
   | `press=70` | 赤い帯に「油圧 70kPa」。警報音が鳴る（エミュレーターは音が出ないので`adb shell dumpsys audio`でアラームの再生を見る）。帯が1分点滅して、そのあと赤のまま止まる |
   | `oil=125,press=70` | 「油圧 70kPa」「油温 125℃」が並ぶ。文字がはみ出さない |
   | `oil=128,water=113,press=70` | 3つ並ぶ。文字がはみ出さない |
   | `normal` | 油圧の帯は5秒たつと消える（作り物の走行で油温が上がっている間は、油温・水温の帯は残る）。右下は「油温・油圧」 |
   | `nopress` | 右下が黄色の「油圧センサー途絶」。油圧の警告は出ない |

   `normal`のままでも、作り物の走行では油圧が2分ごとに2回下がる（5倍速で40秒・88秒ごろ）。2回目は油温・水温の帯と重なる
4. 点滅の暗い側でも文字が読めるか、目で見る

### 4-3. スマホへ入れる（本番の端末なので、了承を取ってから）

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

設定画面の「警報音を鳴らしてみる（約10秒）」で、10秒の音が鳴ることを確かめる。

### 4-4. 本体（UNO Q）へ`field.py`を入れる

SG-2-8の残りと同じ作業（`lap.py`と一緒に`deploy.sh`。記録が一瞬止まるので、了承を取ってから）。
入れる前のスマホには油圧・回転数が来ないので、油圧の警告が出ないだけで、ほかはそのまま動く。

## 5. 知っておくこと

- 鳴っている途中に新しい警告が出たときは、DASHもスマホも最初から鳴り直す（11/4にDASHをスマホに合わせた）
- スマホの設定画面で変えられるのは、油温・水温・音の大きさだけ。油圧の線・点滅の長さ・音の回数はコードの既定値（DASHの既定と同じ）。DASHの設定ファイル（`~/.config/ecocapture-dash.json`）で変えたときは、スマホの`CircuitConfig`の既定も直してビルドし直す
- 油圧の信号（`OilPress`）はまだ無い（SG-4-3の油圧のハーネスと換算）。来るまでは、DASHもスマホも油圧の警告は出ない

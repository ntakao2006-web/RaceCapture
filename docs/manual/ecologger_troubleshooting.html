EcoLogger 困ったときの手順集（ロガー担当向け）

Ver.2（UNO Q）が中心 ／ チームメンバーは当日手順書の6章だけでよい
大原則：記録は電源ONで勝手に始まり、画面・LTE・サーバーとは関係なく続く。迷ったら触らずに走らせる。 現地でソフトは直さない。直すのは設定と、電源の入れ直しまで。SDの消去・フォーマット、本体ログの削除はしない。

1. UNO Qに入る

経路やり方注意
USB（adb）UNO QのUSB-CをPCへ直接。%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe shell
管理画面はOpen-EcoCapture-Web.ps1（EcoCapture-Web\）で 127.0.0.1:8080		ドック経由だとadbは使えない。USBが唯一の電源なら、抜くと電源も切れる
テザリング（ssh）PCとUNO Qを同じテザリングにつなぎ ssh unoq学校などのWi-Fiではuno-q.localが引けないことがある
スマホコースウォーク画面（ラインの登録・周回数）だけ管理画面はスマホからは開けない作り（安全のため）
以下の~/やcurl・dockerで始まるコマンドは、UNO Qの中（adb shell／ssh）で打つ。

2. 症状ごとの対処

症状まずやること → だめなら
記録が始まらない（RECが出ない）電源を完全に抜いて入れ直す（1回）→ SDを抜いて起動（本体だけに記録）→ それでもだめならVer.1・スマホ組に任せる
「● REC（本体のみ）」SDが認識されていない。電源を入れ直す。直らなくても本体(eMMC)に記録中なので走ってよい
管理画面の値が止まる・「MCU未接続」30秒待つ（監視役が自動で「Web停止→ルーター再起動→STM32リセット→Web起動」をする）。戻らなければ sh ~/EcoCapture-Web/flash-mcu.sh --recover。それでもだめならLinuxごと電源の入れ直し
管理画面が開かない（MCUは動いている）docker restart ecocapture-web。原因を見るなら docker logs --tail 50 ecocapture-web
ピット画面に出ない①電源ONから2分待ったか ②送信設定が「LTEだけ」・送信ONか（管理画面のLTE / Podium）③送信の記録 curl -s 127.0.0.1:8080/api/podium/events の最後のreasonを見る ④予備の画面・Podiumで出ているか。記録には影響しない
LTEにつながらない（Network registration timeout）トンネル・建物の中など電波が弱い所では登録に2分以上かかることがある。自動で再試行するので待つ。アンテナのコネクタを押し込む。続くならSIMの残高・SORACOMの状態を見る
送信が途切れる（Relay not respondingなど）自動でつなぎ直す（数十秒〜1分強）。何度も続くなら、サーバー側（自宅のROCK 5B／先輩のサーバー）が動いているか確かめる
声が聞こえない・雑音・途切れる管理画面で「受ける」「送る」をOFF。LTEが混むと音声は自動で止まる作り（テレメトリ優先）なので、それ自体は異常ではない
周回がおかしいその場で直さない。紙の記録表を正にし、走行後にCSVの軌跡から数え直す。ラインを登録し直したら、スマホにQRを読ませ直す
測位しないGNSSアンテナが空を向いているか、コネクタ。起動直後は数分かかる。屋内・車庫の中では測位しない
回収で「UNO Qに接続できません」ドックを外してUSBで直結し、再実行（SD分は回収済み）
Ver.1 ERR点灯電源の入れ直し。終了は必ずSD_Eject.cmd→safeToRemove: trueを見てから電源OFF

3. やってはいけないこと

  • STM32のファームをflash-mcu.sh以外で書き込まない。ルーターが動いたまま書くとLinux側の通信路（ttyHS1）が固まり、Linuxの再起動まで戻らない。
  • 記録中にSDを抜かない。電源OFFを確かめてから抜く。
  • GPIOのgpiogetをSTM32の制御線（BOOT0・NRST・RDY）に使わない（出力が入力に切り替わってしまう）。
  • 試していない設定（Wi-Fi⇔LTEの「自動」、試験で通っていないサーバーのURL）を本番で入れない。

4. 状態を見るコマンド（UNO Qの中で）

見たいものコマンド
MCU・SD・IMU・GNSScurl -s 127.0.0.1:8080/api/status（connected・sd_logging・gnss_errors）
送信の状態・電波curl -s 127.0.0.1:8080/api/podium（state・frames・reconnects・radioのRSRP/SINR）
接続・切断の履歴curl -s 127.0.0.1:8080/api/podium/events（接続までの段階ごとの秒数・切れた理由）
サービスsystemctl is-active arduino-router ecocapture-mcu-supervisor ／ docker ps
アンテナ・置き場所の比較python3 ~/antenna_compare/antenna_compare.py <名前> 180（3分。RSRP -100dBm前後・SINR 10dB以上なら良好）
電波の目安（自宅の屋内、2026-10-22）：RSRP -100〜-104dBm、SINR 13〜15dB。4種類のアンテナに差は無く、つながる基地局で8dBほど変わった。

5. UNO Qを入れ替えるとき（2026-10-21に実際に行った手順）

  1. 古い方から写す（古い方が起動するなら）：ecologger_v2・ecologger_v2_libraries（MsgPackなど）・稼働中のファーム（ecologger_v2_wdog_20261009.bin）・EcoCapture-Web・データの設定（ecocapture-v2-dataのconfig.json・lap.json・field_token・maps・private。logsは不要）・rnnoise_v011・audio_check。PC経由で tar → adb pull → adb push。
  2. 新しい方でWebを作る：cd ~/EcoCapture-Web && sh deploy.sh（テスト込み、root不要）。音声のテストはnumpyが要るので、ネットにつなぐまでは飛ばしてよい。
  3. rootの作業：sudo sh ~/EcoCapture-Web/setup-root.sh "<今のUTC時刻>" ~/ecologger_v2_wdog_20261009.bin。時刻合わせ・ルーター921600bps・起動サービス・監視役・ファーム書き込みまで一度に行う。
    新品は最初にパスワードの変更を求められる（New password:）。決めたパスワードは担当者で控える（紙に書かない）。
  4. 確かめる：/api/statusのconnected: true・sd_logging: 1、LTEで1回送る（antenna_compare.pyでよい）。
  5. まだ入っていなければ：音声エージェント（install-voice-agent.sh、ネット接続が要る）、Wi-Fiの設定、ssh unoq用の鍵。
新しいUNO Qは時計用の電池が無く、電源を切ると時計が戻る。記録の時刻はGNSSのUTCも別に残っているので、走行の解析には困らない。

6. ソフトを更新するとき（大会中はしない）

  • PCから：powershell -ExecutionPolicy Bypass -File .\EcoCapture-Web\Update-UNOQ.ps1（ファームも書くなら -Firmware）。事前に記録を停止。
  • UNO Qの中で：Webはdeploy.sh、ファームはbuild-mcu.sh（ビルド→flash-mcu.sh）。
  • 上書きの前に、UNO Q上のソースは自動で退避される。更新したらコミットの番号を控える（何が入っているか分からなくなるのを防ぐ）。

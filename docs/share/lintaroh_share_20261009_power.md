# Lintarohさんへの共有メモ：映像まわりの機材構成と電源（2026-10-09）

UNO Q（LoggerV2）の**カメラ・モニターの機材構成**を、いったん下の形で考えています。
この構成にした場合、**UPSモジュールとの組み合わせで確認したいこと**が出てきたので、まとめました。
機材や電源の最終的な判断はLintarohさんにお任せします。

---

## 1. いま考えている構成

```
シガーソケット充電器（USB-C PDのポートあり）
 ├─ USB-C ──→ ロガー一式（UNO Q＋シールド＋UPSモジュール）
 │              └─ UNO QのUSB-C ──→ USB-Cドック（HDMI・USB・PD給電パススルー）
 │                                    ├─ HDMI ──→ モニター（映像のみ）
 │                                    └─ USB ───→ USBカメラ（UVC）
 └─ USB-C ──→ PDトリガーケーブル（15V固定）──→ モニターのDC入力
```

| 機材 | 候補 | 理由 |
|---|---|---|
| カメラ | **USB UVCカメラ（H.264出力のもの）** | 表示のためにどのみちドックが要るので、カメラはドックの空いているUSB口に挿すだけで済む。実カメラ→GPU焼き込み→HWエンコードの通しはUSBカメラで動作を確認済み（`unoq_video_check_procedure.md` 5-7）。MIPI CSIは基板が別に要り、まだ試していない |
| モニター | **Portkeys HD7H**（7インチ・1280×720・1000nit・約12,600円） | 明るくて安い。入力はHDMIのみで、タッチパネルは無い |
| モニターの電源 | **PDトリガーケーブル 15V固定**（DSD TECH MagicConn SH-CP15A／SH-CP15B） | ロガーとは別の系統にする。充電器の電圧変換回路が、エンジン始動時の電圧低下や瞬間的な高電圧を受け止めてくれる |
| ドック | 「HDMI＋USB 1口＋PD給電」の小型のもの（未選定） | USBにつなぐ機器はカメラだけなので、ハブは要らない |

補足：

- **カメラはH.264を出せる機種に限ります。** HWデコーダはMJPEGを扱えず、1080pのMJPEGをCPUで展開すると30fpsに間に合わない見込みのためです。機種はこれから手配します。
- **モニターのボタン（F1・F2）とUSB端子はモニター内部の機能用**です。UNO Qにはつながないので、USBの口は増えません。運転中に押すボタンが要る場合は、モニターのボタンではなく、シールドの入力かCANに専用のボタンをつなぐ案を考えています。
- **HD7HのDC入力は7〜24V、5.5mmのDCジャック、最大約10W**です（販売店・レビュー記事3件で一致）。プラグの**内径（2.1mmか2.5mmか）と極性はまだ確認できていない**ので、現物で確認してからトリガーケーブルの型番を決めます。

この方向でよいか、見てもらえるとうれしいです。

## 2. UPSモジュールについて、こちらの理解

送ってもらった「EcoLogger V2 UPS Module」の画像から、次のように理解しています。違っていたら教えてください。

- UNO Qのシールドと同じ形で、**UNO Qとシールドの間に積み重ねる**
- スーパーキャパシター6本とDC-DCコンバーター（L1・U1）で、**入力が途絶えても全体を約10秒動かす**
- Q1・Q2・U2は、電源の切り替えか、入力が途絶えたことの検出をする回路

## 3. 確認したいこと

### 3-1. UNO Qの給電経路

本番では、UNO Qへの給電は**ヘッダー経由（UPSモジュールから）**と**USB-C経由（ドックのPD給電パススルー）**のどちらでしょうか。

5-7の試験では、UNO QのUSB-Cにドックをつなぎ、ドック側から給電していました。
本番でUPSモジュールからも給電すると、**UNO Qに2つの経路から同時に給電される形**になりそうですが、問題ないでしょうか。

### 3-2. ドックとカメラは10秒の保持の対象に入るか

USB-Cドックの多くは、**給電側の電源が一瞬でも途切れると自分自身をリセット**し、つながっているUSB機器とHDMI出力が全部つなぎ直しになります。

UPSモジュールでUNO Qが動き続けていても、ドックがリセットされると次のことが起きます。

- **USBカメラが一度外れて、録画が途切れる**（データロギングは止まらない）
- カメラがつなぎ直されたときに**デバイス番号がずれる**ことがある（5-7で確認済み。プログラムでは名前で探す対策をしている）
- 画面が一時的に消える

ドック（とカメラ）も保持の対象に入るのか、入らないのかを教えてください。
入らない場合は、**充電器の出力が途切れたときにドックがリセットされるか**をこちらで実機で試します。

### 3-3. 入力が途絶えたことをUNO Qに知らせる手段

10秒あれば、**入力が途絶えたことを検出 → SDのログを閉じる → Linuxを正しい手順でシャットダウンする**ところまで回せると思います。
ロガーは「電源ON/OFFでログを開始・終了する」設計なので、ここが**ログを確実に閉じる仕組み**にもなります。

- 入力が途絶えたことを知らせる信号は、STM32かLinuxのどちらかのピンに来ますか（ピン名を教えてほしいです）
- 信号を受けたあとの処理（ログを閉じる、Linuxを止める）は、どちらで実装する想定ですか

### 3-4. 起動時の突入電流と、記録が始まるまでの時間

空のスーパーキャパシターを充電するとき、充電器の過電流保護が働いたり、PDのやり取りが失敗したりしないかが気になっています。
また、**キャパシターの充電が終わるまでロガーが起動しない作りになっていないか**も確認したいです。電源を入れてすぐに記録が始まることが要件のためです。

### 3-5. 充電器のポートを複数使う場合

ロガーとモニターを1台の充電器の別々のポートから取ると、**後から挿した機器のPDのやり取りに合わせて、充電器が全ポートの出力を一度切る**ことがあります。
この瞬断はUPSモジュールで吸収できる想定でよいでしょうか（3-2のドックの問題は残ります）。

## 4. こちらでやること

- H.264出力のUVCカメラを手配し、1080p30が出るかとCPU負荷を確認する
- HD7Hのジャックの内径と極性を確認してから、トリガーケーブルを決める
- 3-2・3-5について、実機で「充電器の出力を切ったときにドックとカメラがどうなるか」を試す（UPSモジュールの扱いが決まってから）

# Lintarohさんへの相談：電源が一瞬切れると、ドックが落ちてモニターとカメラが戻らない（2026-11-05）

Ver.2（UNO Q）は、充電器の出力が一瞬切れても**UPSモジュールのおかげで記録は止まりません**。ありがとうございます。
ただ、**USB-Cドックだけが落ちて、モニターとカメラが次にLinuxを起動し直すまで戻らない**ことが分かりました。
どう直すのがよいか、相談させてください。部品・回路・方式の判断はLintarohさんにお任せします。

**SUGO（11/8）には間に合わなくて大丈夫です。** SUGOは「走行中に電源まわりを触らない」運用で乗り切ります（4章）。

10/9に送ろうとしていた`docs/share/lintaroh_share_20261009_power.md`の3章（UNO Qの給電経路・ドックが保持の対象か・入力が途絶えたことの知らせ方）と重なるところがあります。
あちらへの回答はまだもらっていないと思うので、このメモでまとめて聞きます。

## 1. 今の配線（SUGO用）

```
ヒューズ電源 → 手元スイッチ → 増設シガーソケット → USB-C 2口の車用充電器
  ├─ C1 ──→ ドックのPD給電口
  │          ドック ──[映像対応のType-C延長 2m]──→ UNO QのUSB-C（UNO QもここからPDパススルーで給電）
  │            ├─ HDMI → モニター（HD7H）
  │            └─ USB  → カメラ（ELP、最大500mA）
  └─ C2 ──→ WITRNのPDトリガー 9V → モニター（HD7H）の電源
UNO Q ＋ UPSモジュール ＋ シールド（積み重ね）
```

- 内装の穴の都合で、ドックはモニター側に置き、UNO Qとの間を映像対応のType-C延長でつないでいます（11/4に決めた形。映るかは家で確かめる段階）

## 2. 起きていること

1. 充電器の出力が一瞬切れる（ケーブルの抜き挿し、プラグの接触、エンジン始動時の電圧低下など）
2. UNO QはUPSで動き続ける。**ドックは充電器から直接もらっているのでリセットされる**
3. **UNO QのUSB-Cは、動いている間にドックがつながり直しても見つけられない**
   - 10/29：動いたまま（UPSで保たれたまま）PCからドックへ差し替えると、Type-Cの口に相手が出ず（`/sys/class/typec/port0`だけ）、カーネルの記録にも何も出なかった（`unoq_video_check_procedure.md` 5-9-1）
   - 10/23：起動後のケーブルの抜き挿しでは直らず、`anx7625`ドライバーの読み込み直しは映像側とぶつかって失敗した。**ドックに給電した状態で電源を入れ直すと直る**（`task_ecorun_20261024_breakdown.md` ER-10-8の追記）
4. その結果、**モニター（DASHの画面と油圧の警告音）とカメラ（焼き込み録画）が、次にLinuxが起動するまで止まる**。記録・LTE送信は止まらない

なお、**モニター側（HDMI）の抜き差しやモニターの電源の入れ直しは自動で戻る**ことを10/29に確かめています。弱いのは「ドックのリセット」だけです。

あわせて困っているのが、**直すために電源を入れ直そうとしても、UPSで粘るので完全に落ちるまで長い**ことです（ユーザーの体感。何秒かは測っていません）。
10/9のメモでは「約10秒保持」と理解していましたが、実際はそれより長く感じています。

## 3. 相談したいこと

| # | 内容 | こちらの考え（叩き台） |
|---|---|---|
| 1 | **今のUNO QとUPSモジュールの給電経路**を教えてください。UPSモジュールの入力は、UNO QのUSB-C（ドックのパススルー）から取っていますか。別に入力の口がありますか | 2の答えの前提になるので、まずここを知りたいです |
| 2 | **ドックをUPSの内側に入れられますか** | 一番効きそうだと考えている案：ドックのPD給電口には何もつながず、**ドックはUNO QのUSB-Cから電気をもらう**（バス給電）。充電器はUPSモジュール側へつなぐ。こうすれば一瞬の停電でドックもカメラもリセットされず、つなぎ直しがそもそも起きません。気になるのは、①UNO QのUSB-Cから、ドック＋カメラ（最大500mA）の分を出せるか、②2mの延長での電圧の落ち、③UPSで保てる時間がどれだけ減るか、です |
| 3 | 2が無理なら、**ほかにドックをリセットさせない方法**はありますか | 例えば、ドックのPD給電も停電の間保てる形にする、など。思いつく方法があれば教えてください |
| 4 | **入力が途絶えたことをUNO Qに知らせる信号**は作れますか（10/9の3-3と同じ） | 入力が途絶えて数秒続いたら、ログを閉じてLinuxを正しく止めたいです。一瞬の停電はUPSで吸収し、スイッチを切ったときは十数秒で落ちる形になります。「電源ON/OFF＝記録の開始・終了」の考え方とも合います。信号がSTM32とLinuxのどちらのピンに来るか、何秒待ってから止めるのがよいかを教えてください |
| 5 | **Linuxが止まったあと、UPSの出力も切れますか** | 止まったあとにキャパシターでUNO Qに電気が残り続けると、次に電源を入れたときに起動し直さないのでは、と気にしています。4とセットで考えてほしいです |
| 6 | **UPSで保てる時間は、設計ではどのくらいですか** | 何秒あれば足りるかを決めるため。4・5ができれば、長く保てるほど安心です |

## 4. こちらでやること

- **SUGOは運用で瞬断を起こさない**：全部つないでから手元スイッチを入れる、走行中は充電器の口を抜き挿ししない（2口の充電器は片方を挿しただけで両方の出力を一度切ることがある）、シガーソケットのプラグを奥まで挿して固定する
- SUGO前の通し確認で、**ロガーを入れてからエンジンをかけたときに画面が消えないか**を見ます（始動時の電圧低下で充電器かドックが落ちるか。家では試せないため）
- 画面が消えたときの手順（記録は続いている、ピットで電源を入れ直す）を当日の手順書に書き、予備の車載画面（スマホ。ドックを通らない）を使えるようにしておきます
- ソフトでUSB-Cの口をやり直せないかも、本体で試してみます。ただ10/23に一番素直な方法が失敗しているので、当てにはしていません
- 2の案がよさそうなら、Lintarohさんの指示どおりに机の上で試します（それまでは配線を変えません）

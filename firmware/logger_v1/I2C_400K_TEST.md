# I²C 400 kHz でのBNO055安定性試験（2026-10-10、ToDo t710）

Ver.2でGNSSとBNO055がI²Cを共用するため、Ver.1でI²Cを100 kHz→400 kHzへ上げてBNO055が安定するかを卓上で確かめた。

## 条件
- 基板：ecologger_v1（卓上・車両非接続）、書き込み機 CH9102（COM15）経由
- ファーム：`sensors.cpp` の `cfg.master.clk_speed` を `400000` にしただけの試験版
  （ビルドタグ `logger-v1-i2c400k-test-20261010`）。BNO055は従来どおり0x08から0x33バイト読み（NDOF）
- `getStatus` を30秒ごとに記録（`artifacts/i2c400k_20261010/`）
- 時間：**約24分**（予定の30〜60分に届かず、ユーザー移動のため打ち切り）

## 結果

| 項目 | 100 kHz（基準、起動32秒） | 400 kHz（1,414秒） |
|---|---|---|
| IMU取得 | 3,132件（約98 Hz） | 141,126件、30秒ごとに常に3,014〜3,016件（≒100.5 Hz） |
| `imuErrors` | 0 | **1（起動直後の初期化1回のみ。以後増えず）** |
| `invalidSamples` / `recoveries` | 0 / 0 | **0 / 0** |
| SD記録 | — | 143,523行／1,436秒＝**99.95行/秒**、取りこぼし0・エラー0 |

- 区間レートに97.26 Hzが混じるのは、`uptime`が秒単位の整数で31秒区間になったときの計算上の見かけで、件数自体は毎回同じ
- 起動時の1件は書き込み後のリセットでの起動時に出たもの（BNO055の起動待ちで初期化を1回やり直した分と見ている）。100 kHzでの電源投入起動では0だったので、条件が揃っていない

## 判定
**24分の範囲では400 kHzで安定（取得の欠け・無効サンプル・自動復帰ともに0）。**
回路担当へ「I²Cは1系統でよい見込み」と返せる材料になった。ただし予定より短いので、
確定させるなら残りの時間（＋AMGモード20バイト読みでの試験）を追試する。

# SDカードだけで走行記録を読む

対象は `logger-v1-sd-session-20260831b` 以降です。2026-08-31の屋外試験で実機へ書き込みました。
RaceCaptureは表示用です。SD記録はロガー自身が行い、PCやアプリを外しても続きます。

## 普段の使い方

1. SDカードを入れて電源を入れます。自動で記録を開始します。
2. GPSが測位すると緯度・経度・速度が記録されます。時刻が未確定でも記録は待たせません。
3. 保存を終了するときは、このフォルダーの `tools/SD_Eject.cmd` を実行します。
   `safeToRemove: true` が表示されてから、電源を切り、SDカードを取り出してください。
   エラーやタイムアウトの場合は、取り外し可能と判断しないでください。
4. SDカードの `logs` フォルダーをPCへコピーします。CSVと同名の説明・終了ファイルも残します。
5. `tools/sd_viewer.html` をブラウザーで開き、CSVを選びます。
   対応する `.meta.json` / `.end.json` も一緒に選ぶと、単位と保存完了を確認できます。
6. 軌跡はGPS速度で色分けします。時系列の選択欄でIMUなど任意の列を選べます。
   下のスライダーで、軌跡上の位置とその時刻の値を照合できます。

保存終了操作には現在PC接続が必要です。A105/CH9102書込み機があれば、RaceCaptureとは別の
COMポートを自動選択します。USB-OTGだけの場合は、RaceCaptureを正常終了してから実行します。
電源を入れたままSDを再挿入した場合は `tools/SD_Resume.cmd` で再開します。
通常の電源再投入なら、自動的に再開します。

PCなしで使える保存終了ボタンは未実装です。車載での操作方法・取付位置は別途決める必要があります。
記録中の電源断やSD抜去を安全と保証するものではありません。500 ms同期でも、カード内部の
書込み待ち・FAT更新・ファイル末尾などを保護しきれるとは限りません。

## ファイルの見方

例：`20260831_143025_JST_L1234ABCD_0002.csv`

- 日時部分は、GPS UTCと起動後経過時間から求めた**推定起動日時（日本時間）**です。
- `L1234ABCD` は起動ごとの識別子です。同じ秒に再起動しても区別します。
- `0002` はその起動中のファイル番号です。設定変更、時刻確定、明示的な区切り、256 MiBで分割します。
- GPS時刻が未確定の区間は `L1234ABCD_0000.csv` のような名前です。
  時刻確定時に新しい日時付きファイルへ切り替えます。既存ファイルを改名・上書きしません。
  同じ起動IDで関連付けられ、時刻確定時に閉じた区間の `.end.json` にも推定起動日時を残します。
  それ以前に閉じた区間や、UTCが最後まで不明な区間では日時を推測で埋めません。
- `.meta.json` は各列の単位・更新頻度・有効期限・ファームウェアの識別情報・再起動理由などです。
- `.end.json` は同期と正常終了を確認した後に作ります。行数と累計欠落・エラー数も含みます。
  このファイルがない場合は、旧版、記録中、電源断、終了エラーなどを区別して確認してください。
- `_can.csv` は生のCANフレームです。軌跡表示では全チャンネル側のCSVを選んでください。

`monotonic_us` は起動後の経過マイクロ秒、`utc_us` はGPSと対応付けたUnix UTCマイクロ秒です。
`GPSUTC` はGPSの測位時点のUnix UTC秒、`GPSTow` は測位更新を識別するGPS週内のミリ秒です。
100 HzのCSVには、25 HzのGPS値を次の更新まで保持する行が含まれます。
時刻未確定・無効なセンサー値は空欄です。0と区別してください。

IMUの軸はBNO055基準です。車体の前後・左右への対応は未確定なので、Xを前後Gと断定しません。
`Accel` は重力込み、`Gravity` は推定重力、`GForce` は重力を除いたG値です。
`IMUCal` は校正状態で、完全校正は255です。完全校正と車載環境での精度確認は残っています。
`GPSHAcc` は受信機が報告する精度推定であり、実際の位置誤差を測った値ではありません。

## RaceCaptureの表示とUSB復帰

詳しい動作条件・制限・ファイル構成は [AUTO_RECOVERY.md](AUTO_RECOVERY.md) を参照してください。

RaceCaptureは通常の起動方法で使えます。切断後の自動復帰を使う場合だけ、
`tools/RaceCapture_AutoRecovery.cmd` から起動してください。既に1個起動している場合はそのアプリを監視します。
既存のダッシュボードを残し、GPS/IMU用の `Logger GPS / IMU` を追加しています。
緯度・経度・GPS速度・衛星数・測位状態・GPS更新頻度・UTC有効・欠落数・G値・IMU更新頻度を表示します。
起動時の `Searching for Track` はコース検索です。それだけでGPS未測位とは判断しません。

自動復帰は、アプリ内のセッション記録が実際に進むのを確認してから監視を開始します。
USBポートが戻って安定しているのに、記録の追加が25秒以上止まった場合、アプリへ正常終了を要求して再起動します。
強制終了はしません。正常終了できない場合は止まり、`artifacts/racecapture_guard.jsonl` に残します。
繰り返し再起動は10分に3回までです。アプリの記録設定をOFFにした場合は対象外です。
ユーザーがアプリを閉じると監視も終了します。最初から受信できない場合や、再起動後も全く受信できない場合は手動確認が必要です。

これはアプリが切断後に取得を再開しない問題への回避策です。ケーブルや電源の瞬断自体は修理しません。
アプリ側の記録には停止中の空白が生じます。その間の正式な記録はSD側で確認してください。
Wi-Fiやクラウドへのデータ送信は追加していません。アプリ本体の実行ファイルも変更していません。

## 診断用の操作

- c版のUART限定保守操作 `inspectSd` は、記録停止・クローズ済みのSD全体のファイル数・容量を確認します。
- `clearSd` は同じ停止条件に加えて `confirm: DELETE_ALL_SD_CONTENTS` を明示した場合のみ、
  SD内の全ファイル・サブディレクトリーを削除し、空の `logs` を作ります。復元できる保証はありません。
  外部から削除先パスを指定できず、対象はマウント済みの `/sdcard` に限定します。
  自動記録再開はしません。必要なら `setLogging: true`、または電源を入れ直します。

- `getStatus` の `logging.closed`：保存を停止し、待機中のデータを含めて閉じた状態です。
- `prepareSdRemoval` → `logging.safeToRemove`：同期・クローズ・アンマウントが完了した状態です。
- `setLogging: true`：再マウントして新しいファイルへ記録を再開します。
- `getStatus.system.resetReason` と `.meta.json` の `reset_reason`：再起動の分類です。
  `power_on`、`brownout`、`panic`、`task_watchdog`、`usb` など。`power_on`だけで外部電源断とリセット端子を区別できるとは限りません。
- UART限定の `testUsbReconnect`：`confirm: LOGGER_USB_ONLY` を指定するとUSBだけを1秒切断します。
  本体・SDの再起動やCAN送信は行いません。通常の運用では実行不要です。

CSV閲覧HTMLの解析・描画命令は、実CSV・欠測・不正行・9万行の自動試験に合格しています。
この作業環境ではBrowserスキル経由の `file:` ページ操作がセキュリティ制約で拒否されたため、
ブラウザー画面そのものの自動確認は未実施です。制約を迂回する操作は行っていません。

# EcoLogger V2 / EcoCapture-Web 実機検証（2026-10-02）

USB給電のUNO Q、Logger_V2、実装済みBNO055、屋外へ出したパッシブGNSSアンテナ、既存16GB SDカードで実施。CANの車両配線、LTEのSIM・アンテナ、カメラは接続していません。校正はユーザー指定で後回しです。

## 実装・書き込み

`firmware/ecologger_v2` と `EcoCapture-Web` 0.2.0を実機へ書き込みました。MCUがIMU/GNSS/CANを取得し、SDへ独立して保存します。LinuxはWeb表示とeMMCのCSVを担当します。値をPCで合成しません。

書き込んだMCUイメージは64,172バイト。実際の64KiB領域を超えるビルドは書き込み前に拒否します。RouterBridgeのスタック不足・RPC要求バッファ不足・SD読出し結果を常時状態へ載せる問題を修正しました。SD読み出しは専用RPCを使い、連続セクタは位置設定を繰り返しません。UARTの64バイト受信リングに収まる16バイト単位でアップロードし、64バイトを超えるRPC要求は送信前に拒否します。通常Webの単一共有Bridgeを通して操作します。別の診断RPCクライアントを併用すると受信リングが溢れるため、診断時はWebを停止します。

## 残る範囲と使い方

- BNO055 FW03.11にデータ準備完了割り込みはありません。取得は100Hzタイマー、割り込みは高加速度イベントです。車体軸への取付変換・加速度/磁気校正は未実施です。
- MAX-M10Mの192MHz用OTPは既に承認を受けた一度の処理で設定済み。通常起動はRAM設定だけで4衛星系統・10Hzへ戻し、OTPを再書き込みしません。
- CANはClassic CANの受信専用。125/250/500/1000kbpsに対応します。CAN FD、車両配線、外部通信の高負荷試験は未完了です。終端ジャンパだけで内部受信バッファのoverflowは説明できません。
- LTEは通常ファームでは電源OFFです。ネットワーク接続・PPPは未実装です。SIM・アンテナ接続後の通信試験、撤去したTVSの交換が残っています。LTE GNSSを基準にする校正手順と精度は未検証です。
- この16GBカードは既存の256MiB FAT32パーティションだけを使用しています。カードをフォーマットせず既存データを保持しました。連続1MiBの空きが不足するとSD記録はエラーになり、eMMC側は継続します。
- SD記録は1MiBずつ予約するため、停止した短いファイルも1MiBを占有します。突然の電源断では末尾約1秒がファイルサイズに反映されない可能性があります。電源断耐久試験は未実施です。
- `hardware.dropped`はLinuxへ渡せなかった件数で、Web停止試験・起動待ちで増えます。独立SD側の欠落は`sd_queue_dropped`で区別します。

USB接続で `EcoCapture-Web/Open-EcoCapture-Web.ps1` を実行し、`http://127.0.0.1:8080/` を開きます。通常は自動記録です。SDをダウンロード/コピーする場合は記録を停止します。読み出しには時間がかかります。`sd_decode.py`でBINをCSVへ変換し、破損があればエラーで停止します。

旧経路で途中までしかダウンロードできなかったEL000013.BINは、ローカルでは`.partial.BIN`として区別しています。検証済みの完全な取得データはEL000026.BINとEL000038.BINです。

# ドライバーの声の無音判定（ER-10-9）

ドライバーはボタン無しの常時接続なので、ロガーが「声が出ている間だけ送る」を判定する。
判定はRNNoise（xiph、BSD）の「声らしさ」（10msごと、0〜1）で行い、`voice_gate.py`の`VoiceGate`が
開く（2フレーム連続で0.6以上）・前100msを付けて送る・声が途切れて400ms後に閉じる、を受け持つ。

## RNNoiseは旧版（v0.1.1）を使う
最新版（v0.2、2024年のモデル）は重く、UNO QのCPU（Cortex-A53）では実時間に間に合わない。
自宅サーバー（RK3588）で、10msの音を処理する時間をC言語で測った結果（2026-10-15）：

| 版 | Cortex-A76（速いコア） | Cortex-A55（UNO QのA53に近い遅いコア） |
|---|---|---|
| v0.2（最新） | 2.3 ms | **11.4 ms（実時間に間に合わない）** |
| **v0.1.1（旧版）** | 0.19 ms | **0.8 ms（1コアの約8%）** |

ビルド（autoconf不要）：
```
git clone https://github.com/xiph/rnnoise.git && cd rnnoise && git checkout v0.1.1
gcc -O2 -fPIC -shared -Iinclude -Isrc -o librnnoise_old.so src/denoise.c src/rnn.c src/rnn_data.c src/pitch.c src/kiss_fft.c src/celt_lpc.c -lm
```
Pythonから1フレームずつctypesで呼ぶと、呼び出しのたびのコピーで速いコアでも約0.1ms余分にかかる。
UNO Qに載せるときは、判定の部分をCで書くかnumpyの配列をそのまま渡す形にする。

## 試験（`gate_test.py`）
PCの音声合成（Haruka）で作った無線の短文6本を、合成した車内の騒音（エンジン80Hz＋倍音・ロードノイズ・風切り）の上に
120秒の中で散らして置き（声は全体の12.3%）、騒音の大きさを3段階に変えて測った（2026-10-15、旧版）：

| 騒音 | 声との差 | 送った時間 | 声を送れた割合 | 声の無い所で送った割合 | 声から1秒以上離れた所での誤送信 |
|---|---|---|---|---|---|
| 静か | 21dB | 21.3% | 99.5% | 10.3% | **0.0%** |
| 大きい | 11dB | 20.5% | 99.1% | 9.5% | **0.0%** |
| とても大きい | 3dB | 20.1% | 98.6% | 9.1% | **0.0%** |

「声の無い所で送った割合」は、ほぼすべてが語の切れ目と語尾の後の保持（400ms）。
比較した単純な音量判定（騒音の底から+6dB）は、ロードノイズのゆらぎで**99.8%送りっぱなし**になり使えない。
送る時間が全体の約2割なら、ドライバーの上りは垂れ流しの約1/5（1時間で約1〜1.5MB）。

**注意**：騒音は合成で、声は音声合成のきれいな声。実車の騒音・ヘルメット越しの声では違う可能性がある。
UNO QにUSBオーディオがつながったら、実車で録音して同じ試験をする。

ロードスター（NCEC）・SUGO 120分耐久（2026-11-08）を走った形

EcoLogger Ver.2 構成図

Ver.2ロガーが、車のどこから電気と信号をもらい、何を記録して、どうやってピットの画面まで届けているかをまとめた図です。図の上下は実物の積み重ねの順に合わせています。後半は、それを動かしているソフトウェアの図です。

車の中のつながり

ロガー本体は3枚の基板の積み重ねです。一番下がArduino UNO Q、その上にUPSモジュール、一番上にシールド（logger_v2）が載ります。アンテナ2本はシールドにつながります。

  • UNO Qの電気は、充電器のC1 → ドックのPD給電口 → Type-C延長 → UNO QのUSB-C、の順に来ます。UPSモジュールはUNO QのUSB-Cから入った電気を受け、ためておきます。
  • ドック1本で、UNO Qへの給電・HDMIの映像と音・カメラのUSBをまとめています。モニターの電源だけは充電器のC2からPDトリガーで9Vにして別にもらいます。
  • 車両CANはOBD2のタップから受信だけで読みます（ロガーから車へは送りません）。Defiの油圧・油温・水温は、既設のセンサーの電圧をPICのセンサーハブが分けて読み、CAN2で送ります（ID 0x580）。ハブの電源も同じ4本の線（+5V・CAN-H・CAN-L・GND）でシールドからもらいます。
  • 記録は2か所に残ります。UNO Qの本体（eMMC）と、シールドのmicroSD（控え。いっぱいになると古い順に消して続けます）です。

LTEでピットの画面に出るまで

ピットの画面に出る値は、シールドのLTEモジュールから携帯の回線とインターネットを通って自宅のサーバーに届き、そこでグラフと地図になります。ピットではスマホやPCのブラウザでそのページを開いて見ます。

  • LinuxとLTEモジュールは直接はつながっていません。Linuxがまとめた値をSTM32へ渡し、STM32がシールドのUART（2Mbps）でSIM7070Gへ送ります。
  • 回線はSORACOMのSIM（planX3）で、その場で一番よい携帯会社の基地局につながります。SUGOではドコモのLTEにつながっていました。
  • 自宅のサーバーの入口は1つで、ロガーの受け口・Grafana・地図をまとめて出しています（アドレスはここには書きません）。

外から本体へつなぐ3つの道

PCやスマホから本体へは、USBのadb・テザリング・LTEの3つの道でつなぎます。いちばん大きな違いは、USBとテザリングはLinuxの中まで入れるので何でもできるのに対して、LTEは値を受け取るのと、決まった5つの命令を送ることしかできないところです。そのかわりLTEだけは走っている最中もつながります。

  • シールドのmicroSD（控えの記録）はどの道でも取らず、本体の電源を切ってカードを抜き、PCのカードリーダーで回収します。

ロガー本体の中のソフト

UNO Qの中には頭脳が2つあります。STM32（マイコン）が測定と記録の土台で、Linuxがその値を使って記録・画面・録画・LTE送信をします。STM32はLinuxが止まっても測定とmicroSDへの記録を続けます。

  • 値の流れ：STM32が100Hzで取った値は、microSDへ書くのと同時にArduino Routerを通ってLinuxのEcoCaptureへ渡ります。EcoCaptureが本体への記録・ラップ・LTE送信をまとめ、車載画面（DASH）と焼き込み録画はEcoCaptureから値を読みます（録画は約25Hzで読み、映像の時刻に合わせて補間）。
  • LTEで送る道：送るデータを作るのはLinuxのEcoCaptureですが、モデムをつないでいるのはSTM32です。なので、Linux → Router → STM32 → UART → SIM7070G の順に出ていきます。
  • 止まっても続ける仕組み：STM32はLinuxがいなくても記録を始め、ループが30秒止まると自分で再起動します。STM32が再起動したあとLinuxとの通信が戻らないことがあるので、Linuxの「通信の見張り」が30秒以上の切断を見つけて元に戻します。「障害の記録」は、突然電源が切れたときの直前の様子を残します。
  • EcoCaptureはDockerのコンテナの中で動き、PCからはUSBのadbでその設定・ログの画面を開きます。コースウォーク画面だけは車の中のWi-Fiに出していて、スマホから合言葉付きで開きます（ライン登録と、予備の車載画面への値だけ）。
  • 公式のRaceCaptureアプリは入ったままです。SUGOからは車載画面をDASHに切り替えていて、切り替えで戻せます。
  • PICセンサーハブのファームは回路担当が作ったもの、それ以外の本体のソフトは基本こちらで作っています。

本体の外のソフト

ロガーから出た値は自宅のサーバーでグラフと地図になります。PCの道具は、本体の操作・回収・設定と、大会後の解析に使います。

  • 受け口のecorun-logger-serverはチーム（Maruo.Sさん）が作ったサーバーで、Dockerで動かしています。届いた値を部屋（車）ごとのファイルに書き、live_bridge.pyがそれを追いかけて、保存（VictoriaMetrics）と、地図・周回表へのなめらかな配信をします。
  • PCからの命令（周回数の直し・記録の開始など）は、自宅のサーバーを通って同じLTEの道でロガーへ届きます。命令には合言葉の署名を付け、ロガーは決まった命令しか受け付けません。
  • 回収・設定の道具はデスクトップの「EcoLogger Ver.2」（操作メニュー）からボタンで開けます。本体へはUSBのadbか、スマホのテザリング経由のsshでつなぎます。

分かっている弱点・これから

  • 電源が一瞬切れると、UPSの外にあるドックだけがリセットされ、モニターとカメラが次にLinuxを起動し直すまで戻りません。記録とLTEの送信は止まりません。ドックをUPSの内側に入れる案を相談中です。
  • ブレーキ圧センサー（AiM、0.5〜4.5V出力）を足す予定です。電源が8〜16Vなので、シールドの5Vではなく12Vを別に引きます。
